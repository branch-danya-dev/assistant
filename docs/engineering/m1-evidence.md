## Implementation choices within accepted ADRs

- Reuse the approved jsonschema dependency at runtime, pinned to tested 4.26.0; no new provider
  SDK. All schemas/configs come from canonical spec/. Builds copy those resources into wheels.
- One OS-released lock serializes execution/recovery. Stop and inspection use independent
  SQLite connections. No persistent application daemon or automatic background retry.
- Atomic pre-dispatch record + approval consumption. Unknown effects require owner reconciliation;
  even a verified 'not applied' outcome needs a fresh task/approval, never replay of old action.
- SQLite version-1 migration is transactional. Backup uses online API + integrity_check. Rollback
  restores a verified backup with matching code; no destructive automatic down migration.
- Private task payloads live only in local DB outside Git. Audit events contain IDs, codes and
  digests, not source/model text. Persona lives in data/identity. No automatic remembering.
- Production registry contains only read_text and search_memory. Other operations fail closed;
  a capability listed in spec/capabilities.json does not activate an executor.

## Remaining work and limits

- TASK-009 / REQ-010: plans currently have sequential dependencies and a fixed saved step list;
  audited in-task replanning is not implemented. TASK-010's final gate follows this work.
- TASK-043 / REQ-025: safe create-only workspace writing, including parent-replacement races,
  is not implemented. Existing-file modification/deletion and real external effects remain disabled.
- REQ-017/019 retain specified/partial status: current closed tool and local-egress boundaries
  pass their tests, but generic detection of secret text, OS vault integration and future
  browser/cloud adapters are not certified by these fixtures.
- Removal means auditable exclusion from retrieval/indexes, not secure deletion of DB pages or
  backups. Semantic retrieval, full privacy export/erasure and persona editor remain later work.
- Final language-model prose is explicitly labelled unverified summary of verified tool results;
  task completion proves the saved steps, not universal factual correctness of generated text.
- No distributed/multi-user service, scheduler, browser/office integration or physical GPU
  performance claim. This evidence is not a blanket M1 completion assertion.

Next concrete implementation: audited plan revision preserving completed action IDs and
non-replay invariants, then create-only writes under the same scope and journal boundaries.
